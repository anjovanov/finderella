# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Finderella** — a Plex/Jellyfin-style media streaming web app (movies + series) with a **distributed backend**: the SvelteKit app ("hub") runs on a storage-poor VPS; media lives on the user's other devices, each running a Node storage gateway — the media agent (`packages/storage-gateway`, bin `finderella-storage-gateway`) — that dials out to the hub over one WebSocket and serves file ranges + ffmpeg HLS transcodes through that tunnel. Dark cinematic theme (forced dark, teal accent).

### Built so far

- **Pages**: Home (hero banner + landscape carousels), `/movies` & `/series` libraries (portrait grids, genre/sort filters), `/categories` (row per genre), detail pages (`/movies/[id]`, `/series/[id]` with season tabs + episode carousel), watch pages (`/movies/[id]/watch`, `/series/[id]/watch/[episode]`), styled 404.
- **Search**: single nav-bar search; live-filters library pages via `?q=` (debounced `goto` with `replaceState`), Enter navigates from other pages.
- **Data layer**: pages read the catalog from Postgres via server loads calling `src/lib/server/catalog.ts` (async queries returning the exact `src/lib/data/types.ts` shapes; public IDs are slugs). `src/lib/data/` keeps: `types.ts` (the frontend contract), `hrefs.ts` (client-safe `mediaHref`/`watchHref`/`episodeWatchHref` via `resolve()`; `watchHref` sends a series to its next-in-line episode), `episodes.ts` (pure `flattenEpisodes`/`playTarget`/`episodeLabel` — `playTarget` reads `Series.lastWatchedEpisodeId` + episode `progress`, stamped by `applyProgress`, to pick resume-latest-else-next; heroes label it `Resume S2E4`), and pure helpers (`topRated`/`byGenre`/`allGenres` — items passed in). There is no mock/seed corpus: titles only come from gateway scans, and `catalog/prune.ts` removes titles left without any `media_file` (after each scan, and via "Remove titles without files" in settings). Artwork is a deterministic CSS-gradient from per-title hues (`PosterArt`, slug hash) with `posterUrl`/`backdropUrl` images overlaid when set.
- **Backend** (Phases 0–4 built & verified): npm workspaces — `packages/protocol` (zod message schemas + binary framing: 6-byte header `UInt32BE requestId | flags(FIN) | reserved`, hub ids odd / gateway even), `packages/storage-gateway` (CLI: `pair`, `connect`; ffprobe scanning, credit-gated file transfers, ffmpeg HLS transcode sessions; resolves ffmpeg/ffprobe from env → system PATH → bundled `ffmpeg-static`/`ffprobe-static`). Hub: `src/lib/server/gateways/` (WS auth by per-gateway token sha256; `registry` = connection map + request correlation + `openByteStream` with credit-based backpressure), `src/lib/server/streaming/` (compat matrix, source picker, session manager, hub-synthesized VOD HLS playlists), `src/lib/server/catalog/` (filename→catalog ingest + parser + orphan prune), `src/lib/server/metadata/` (TMDB provider: `tmdb.ts` client + zod schemas, `map.ts` pure genre/maturity/match mapping, `index.ts` `enrichPending` single-flight runner triggered after scans, at boot, and by "Refresh all metadata" in settings), `src/lib/server/progress.ts` (watch positions, continue-watching, `loadProgress`/`applyProgress`/`withProgress` stamp a 0–1 `progress` onto items + episodes in every browsing loader and the series watch loader (its `show` feeds the player's episodes panel); thresholds in client-safe `src/lib/data/progress.ts`). Auth gate lives in `hooks.server.ts` (redirect to `/login`; public: `/login`, `/api/auth`, `/api/gateway/pair`; `/api/stream/*` short-circuits Better Auth entirely — stream URLs authorize by unguessable playback-session uuid). Admin UI at `/settings/devices` (pairing codes, libraries, rescan, rename/revoke/remove, catalog prune, metadata refresh). Watch pages create sessions client-side via `POST /api/playback/start` → `{mode: direct|hls, src, sessionId, quality}` (optional `quality` from the ladder in `src/lib/playback-quality.ts`: `original` = direct play when compatible else source-res transcode (≤3840 wide); `2160p|1080p|720p|480p|360p` force HLS with `-maxrate` caps for slow remote uplinks; responses carry `source.{width,height}`) (404/503 with a readable message when the title has no file / its device is offline); progress reports throttle to `/api/progress`; resume via `startAt`/`startSeconds`.
- **Media components** (`src/lib/components/media/`): `Carousel` (snap scroll, edge fades, hover arrows; `gutter` prop defaults to `page-gutter` — override for embedded surfaces), `PosterCard` (poster/backdrop variants), `MediaRow`, `HeroBanner`, `DetailHero` (Play/Resume + optional Watch trailer), `TrailerDialog` (YouTube embed in a `ui/dialog`, iframe mounted only while open), `ProgressLine` (3px watch-progress bar under `PosterCard`/`EpisodeCard`; always reserves its height so titles align), `EpisodeCard` (always-visible corner play badge; `active` shows a teal equalizer "now playing" state, `onNavigate` callback), `LibraryPage`/`LibraryToolbar`, `WatchPlayer`, `EpisodesPanel`.
- **Video player** (`WatchPlayer`): Video.js v10 beta custom elements (`@videojs/html`, exact-pinned) with a fully custom Netflix-style control bar (seek slider w/ hover time, centered play ±10s, volume flyout, captions menu, cast, fullscreen), auto-hide controls + top bar + cursor, keyboard shortcuts (space/arrows). Watch pages are `ssr = false`. Series-only extras (via optional `show`/`currentEpisodeId` props, passed only by the series watch page): "More Episodes" button (left cluster) opening `EpisodesPanel` — a bottom-sheet with season pills + episode carousel; a "Quality" menu (gear icon, right cluster; Original/2160p/1080p/720p/480p/360p filtered by the source width via `availableQualities`, the Original row shows the resolved resolution + direct/transcoded; persisted in localStorage `finderella:quality`; picking a rung makes the watch page restart the session at the current position via `onQualityChange`), an "Autoplay" switch (right cluster, on by default, persisted in localStorage `finderella:autoplay-next`) that autoplays the next episode on `ended` with a "Next episode starting in…" countdown pill over the last 10s. Playback auto-starts whenever the player mounts or is re-sourced (blocked by browser policy on cold loads — caught, stays paused).

### Hard-won gotchas (do not regress)

- **`@videojs/html` is beta**: seek buttons, fullscreen, and keyboard shortcuts are deliberately implemented against the native `<video>`/DOM instead of library elements (its store snapshots/fallbacks are buggy). Keep the exact version pin. HLS goes through hls.js whenever `Hls.isSupported()`; native `<video src=m3u8>` only where MSE is missing (Safari/iOS) — Edge answers `canPlayType('application/vnd.apple.mpegurl')` with "maybe" and then fails with `DEMUXER_ERROR_COULD_NOT_PARSE`.
- The fullscreen-only `filter: brightness(1.001)` on the video defeats a Chromium hardware-overlay bug that paints video above DOM controls. Don't remove it.
- ESLint enforces `svelte/no-navigation-without-resolve`: build hrefs via `resolve()` (see `mediaHref`/`watchHref`); vendored `src/lib/components/ui/**` is exempted in `eslint.config.js`.
- Icons: **hugeicons only** (`components.json` iconLibrary); shadcn-svelte style is **maia**.
- `page-gutter` utility (layout.css) = shared horizontal page padding incl. `scroll-padding` for snap carousels — use it, don't hand-roll `px-*` gutters.
- Player top bar lives **inside** `<media-container>` (hover = player activity; visible in fullscreen). Carousel arrows are positioned via `top` offsets, not `-translate-y-1/2` (Button's `active:translate-y-px` overwrites translate).
- Episode→episode navigation stays on the same route, so the **page component** is reused (EpisodesPanel closes via `onNavigate`); the player itself unmounts briefly between episodes while the new playback session is created (`{#if playback}`).
- The controls library has no pin-open API: while `EpisodesPanel` is open, a `.menu-open` class on `.player-root` CSS-overrides the library's `data-visible` auto-hide (and `chromeVisible` keeps top bar/cursor shown). Panel and countdown pill must live inside `<media-container>` to be visible in fullscreen.
- **ffmpeg's mov/hls muxer rebases fmp4 timestamps to 0 every run** — `-copyts`/`-output_ts_offset` do NOT survive into segment `tfdt`. After a seek-restart the gateway binary-patches each segment's tfdt (+startSegment×4s per track timescale, `packages/storage-gateway/src/transcode/mp4-patch.ts`); hls.js/MSE place fragments by tfdt, so don't remove this. Segment grid: 4s fmp4, `-force_key_frames expr:gte(t,n_forced*4)`; the hub synthesizes the full VOD playlist from probed duration (instant seekbar).
- HLS v1 always re-encodes (libx264 veryfast + aac) to **8-bit H.264 High yuv420p** — level 4.1 up to 1080p, 5.2 above, ≤3840 wide (`-pix_fmt yuv420p -profile:v high -level <plan>`). Without the pix_fmt pin, 10-bit HEVC sources (most x265 MKVs) silently produce H.264 High 10, which browsers' MSE reject — ffmpeg exits 0 and the player spins forever. The level/CODECS pair comes from `transcodePlan()` in `src/lib/playback-quality.ts` (hub sends the plan in `session.start`; the master playlist's `CODECS` uses `plan.codec`) — keep gateway flags and plan in sync. HDR sources (PQ/HLG, detected per session via `probeColorTransfer`) are tone-mapped to BT.709 with `zscale`+`tonemap` (needs libzimg — present in the bundled static build). ffmpeg's own `playlist.m3u8` is the gateway's segment-readiness signal, so `hlsArgs` uses `-hls_playlist_type event` — with `vod`, ffmpeg writes that playlist only on exit and every `hls.get` times out. A `-c copy` remux fast-path is deliberately absent: stream-copy splits segments on existing keyframes and would break the fixed grid the synthesized playlist assumes.
- Keep the `/api/stream/` short-circuit FIRST in `hooks.server.ts` — segment fetches arrive every few seconds per viewer and must not hit Better Auth's DB session lookup.
- `fs.stat().mtimeMs` is fractional; DB `bigint` columns reject it (round before insert). `watch_progress` uses partial unique indexes — `onConflictDoUpdate` needs the matching `targetWhere`.
- **No DB-level defaults on array columns** (`cast_members`/`genres` use runtime `.$default(() => [])`): drizzle-kit introspects an empty-array DDL default as `'{""}'`, so any `.default([])`/`sql` form makes every `db:push` re-propose the same ALTERs forever.
- The hub is **single-process by design**: `GatewayRegistry` + `SessionManager` are in-memory maps (revisit before any horizontal scaling).
- TMDB enrichment (`src/lib/server/metadata`) never rewrites `slug` or `hue`/`hue2` (slug = URL + ingest key). Both matched and unmatched titles get `metadata_updated_at` stamped, so scans don't re-search misses; only "Refresh all metadata" (force) retries. It also stores cast headshots (`cast_people` jsonb: name/character/photoUrl), season posters, episode stills, movie budgets and a YouTube `trailer_key` (`pickTrailer` in `map.ts`: trailer > teaser, official, English; `DetailHero` shows **Watch trailer** → `TrailerDialog` YouTube embed only when set). Artwork is hotlinked from `image.tmdb.org` (no hub-side cache); the settings page carries the required TMDB attribution.
- Filename parser (`catalog/parse.ts`): a show folder name is cut at the first year, season-pack marker (`S01`, `Season 1-3`, `Complete`) **or full episode marker** (`Show S12E02 Title 1080p…/`, the single-episode release layout), and when the folder carries no year it falls back to the filename prefix before the marker (`Invincible.2021.S04E01`) — never to anything after it (episode titles contain numbers). Loose files in the library root take the show name from the filename prefix; a file with nothing before the marker is skipped.
- TMDB matching (`pickBestMatch`) **requires a title hit**; the year is only a bonus/tie-break. Ingest stores the file's mtime year when the filename has none, so `findTmdbId` retries without the year whenever the year-filtered search yields no acceptable candidate (TMDB's year filter hides the real title). A forced refresh ("Refresh all metadata") drops the stored `tmdb_id` and re-searches from `scanTitleFromSlug` (the slug is the only field a wrong match can't have overwritten).
- Dev gateway auth: `GATEWAY_DEV_TOKEN` in `.env` self-registers a "Dev Gateway" row (dev mode only; needs one signed-up user first). Real gateways pair via `/settings/devices` → `npx finderella-storage-gateway pair --hub <url> --code <code>`.

## Commands

- `npm run dev` — start dev server (`-- --open` to open browser); serves `/gateway/ws` via a Vite plugin
- `npm run build` / `npm run preview` — production build / preview it
- `npm run start` — run the production build via `server/index.js` (adapter-node handler + gateway WS upgrades)
- `npm run gateway:dev -- connect [--hub URL] [--token T]` — run the storage gateway (media agent) from source (env: `FINDERELLA_HUB`, `FINDERELLA_TOKEN` or dev `GATEWAY_DEV_TOKEN`)
- `npm run test` — vitest (protocol framing, filename parser, mp4 tfdt patching, HLS ffmpeg args, TMDB mapping)
- `npm run check` — typecheck with svelte-check (`check:watch` for watch mode)
- `npm run lint` — prettier check + eslint; `npm run format` to auto-format
- `npm run db:push` — push schema changes directly to the database (dev workflow; migrations in `drizzle/` are for fresh prod bootstrap via `db:migrate`)
- `npm run db:generate` / `npm run db:migrate` — generate SQL migrations / apply them
- `npm run db:studio` — open Drizzle Studio
- `npm run auth:schema` — regenerate `src/lib/server/db/auth.schema.ts` from the Better Auth config in `src/lib/server/auth.ts` (run after changing auth plugins/options)

Verify with `npm run test`, `npm run check`, `npm run format && npm run lint`, and dev-server smoke tests.

A `.env` file is required (see `.env.example`): `DATABASE_URL` (PostgreSQL), `ORIGIN`, `BETTER_AUTH_SECRET`, and optionally `GATEWAY_DEV_TOKEN` (dev-only shared gateway token) and `TMDB_API_KEY` (metadata/artwork; v4 read token or v3 key). `drizzle.config.ts` and the db client both throw if `DATABASE_URL` is unset.

## Architecture

SvelteKit 2 + Svelte 5 (TypeScript), Tailwind CSS v4 (via the Vite plugin, no tailwind config file — theme lives in `src/routes/layout.css`), Drizzle ORM on postgres.js, Better Auth for authentication, **adapter-node** (custom prod server `server/index.js` owns the `/gateway/ws` WebSocket upgrade, bridged from the SvelteKit bundle via the `init` hook's `globalThis.__finderellaGatewayUpgrade`). npm workspaces: repo root is the web app; `packages/protocol` (shared zod schemas, exports source TS — bundled via `ssr.noExternal`) and `packages/storage-gateway` (CLI). Runtime deps live in `dependencies` (not devDependencies) so `npm ci --omit=dev` works on a VPS.

**Svelte runes mode is forced** for all project files via `vite.config.ts` compiler options — use `$state`, `$derived`, `$props`, etc.; legacy reactive syntax will not compile. There is no `svelte.config.js` — SvelteKit config lives inline in `vite.config.ts` (which also sets `ssr.noExternal` for `@hugeicons/svelte`).

Theme tokens (oklch, dark forced via `class="dark"` in `src/app.html`) and custom utilities (`page-gutter`, `scrollbar-none`, `hero-fade-*`) live in `src/routes/layout.css` — don't move it (components.json / prettier point at it).

### Server-side layout (`src/lib/server/`)

- `db/index.ts` — exports the `db` Drizzle client, initialized from `$env/dynamic/private`.
- `db/schema.ts` — barrel re-exporting `auth.schema.ts` + `catalog.sql.ts` (movie/series/season/episode) + `gateways.sql.ts` (gateway/pairing-code/library/media_file) + `playback.sql.ts` (playback_session, watch_progress). Drizzle Kit reads only this file.
- `db/auth.schema.ts` — **generated** Better Auth tables. Don't hand-edit; regenerate with `npm run auth:schema`.
- `auth.ts` — Better Auth instance (`better-auth/minimal`), Drizzle adapter, email/password. The `sveltekitCookies` plugin must remain last.
- `gateways/` — `ws.ts` (upgrade auth + message dispatch), `registry.ts` (live connections, request/resp correlation, credit-backpressured byte streams), `scan.ts` (trigger library scans).
- `catalog.ts` / `catalog/{parse,ingest}.ts` — catalog queries returning frontend shapes; filename→metadata parsing and scan ingestion.
- `streaming/` — `compat.ts` (direct-play matrix), `source-picker.ts` (best online file), `session-manager.ts` (hot sessions, idle reaper, orphan cleanup at boot), `hls-playlist.ts` (synthesized VOD playlists).
- `metadata/` — TMDB enrichment (`tmdb.ts` client, `map.ts` mapping, `index.ts` runner + `metadataStatus`).
- `progress.ts` — watch positions + continue-watching; `log.ts` — pino.

### Auth flow

`src/hooks.server.ts`: `/api/stream/*` short-circuits before any auth (capability-uuid sessions); everything else resolves the Better Auth session into `event.locals` and redirects unauthenticated requests to `/login` (public: `/login`, `/api/auth/*`, `/api/gateway/pair`). `/login` has sign-in/sign-up form actions calling `auth.api.*`; sign-out lives on `/settings/devices`. Gateways authenticate with bearer tokens on the WS upgrade — never cookies.
