# Architecture reference

Detailed per-feature reference for Finderella. `CLAUDE.md` holds the summary, conventions and hard-won gotchas; this file holds the detail. When a feature changes, update its section here (and add a dated entry to `docs/changelog.md`).

## Pages

Home (hero banner + landscape carousels), `/movies` & `/series` libraries (portrait grids, genre/sort filters), `/categories` (tile grids for Genres / Collections / Networks & Studios → `/categories/[type=category]/[slug]`, a `LibraryPage` with `showKind` + a Movies/Series filter; see **Categories** below), detail pages (`/movies/[id]`, `/series/[id]` with season tabs + episode carousel), watch pages (`/movies/[id]/watch`, `/series/[id]/watch/[episode]`), styled 404.

## Search

Instant, typo-tolerant search over movies + series. **MiniSearch** index in process memory (`src/lib/server/search/`: `engine.ts` is the pure, tested ranker — fields `title`×8, `yearText`×3, `people` (director/creator + cast)×3, `tagline`×1.5, `synopsis`×1; prefix on every term, fuzzy 0.2 (max 2 edits) only on non-numeric terms longer than 3 chars, exact-title bonus, AND first then OR fallback, `normalizeTerm` strips diacritics on index **and** query; `index.ts` is the singleton — `searchCatalog`, `invalidateSearchIndex` (mark stale → rebuilt on the next query, single-flight; called from `finalizeScan`, `pruneCatalog` and the end of `enrichPending`) and `warmSearchIndex` (boot `init` hook)). `GET /api/search?q=&limit=` (`src/routes/api/search`, ≤50) returns `SearchResult[]` (`src/lib/data/search.ts`: kind/slug/title/year/posterUrl/genres/score; auth is the hook's — 401 when login is required, open in guest mode). Navbar `SearchBox` (`src/lib/components/search-box.svelte`, desktop `dropdown` + mobile-sheet `inline` layouts): 150 ms debounce, `AbortController` + sequence guard against out-of-order responses, hand-rolled `role=combobox`/`listbox` with ↑/↓/Enter/Esc, poster thumb + Movie/Series `Badge` per row, "See all results" footer; Enter with no row highlighted → **`/search?q=`** (`searchHref`), whose loader hydrates the ranked slugs via `getMoviesBySlugs`/`getSeriesBySlugs`, re-applies the hit order and renders `PosterCard showKind` in a grid. Library pages no longer read `?q=` (genre/sort filters only).

## Data layer

Pages read the catalog from Postgres via server loads calling `src/lib/server/catalog.ts` (async queries returning the exact `src/lib/data/types.ts` shapes; public IDs are slugs). `src/lib/data/` keeps: `types.ts` (the frontend contract), `hrefs.ts` (client-safe `mediaHref`/`watchHref`/`episodeWatchHref` via `resolve()`; `watchHref` sends a series to its next-in-line episode), `episodes.ts` (pure `flattenEpisodes`/`playTarget`/`episodeLabel` — `playTarget` reads `Series.lastWatchedEpisodeId` + episode `progress`, stamped by `applyProgress`, to pick resume-latest-else-next; heroes label it `Resume S2E4`), and pure helpers (`topRated`/`byGenre`/`allGenres` — items passed in). There is no mock/seed corpus: titles only come from gateway scans, and `catalog/prune.ts` removes titles left without any `media_file` (after each scan, and via "Remove titles without files" in settings). Artwork (`PosterArt`) is a flat `bg-muted` box with the title + year centered until the `posterUrl`/`backdropUrl`/still is **fully** loaded, then the image fades in over 100 ms (`LoadedImage`: `opacity-0` until `load`/`complete`, `decoding="async"`; a failed load keeps the placeholder). Titles without artwork keep the gray box permanently. `hue`/`hue2` are still stored and typed (`theme`) but no longer rendered.

## Backend

### Workspaces, gateways, streaming, metadata, progress

(Phases 0–4 built & verified): npm workspaces — `packages/protocol` (zod message schemas + shared language table + binary framing: 6-byte header `UInt32BE requestId | flags(FIN) | reserved`, hub ids odd / gateway even), `packages/storage-gateway` (CLI: `pair`, `connect`; ffprobe scanning, credit-gated file transfers, ffmpeg HLS transcode sessions; resolves ffmpeg/ffprobe from env → system PATH → bundled `ffmpeg-static`/`ffprobe-static`). Hub: `src/lib/server/gateways/` (WS auth by per-gateway token sha256; `registry` = connection map + request correlation + `openByteStream` with credit-based backpressure), `src/lib/server/streaming/` (compat matrix, source picker, session manager, hub-synthesized VOD HLS playlists), `src/lib/server/catalog/` (filename→catalog ingest + parser + orphan prune), `src/lib/server/metadata/` (TMDB provider: `tmdb.ts` client + zod schemas, `map.ts` pure genre/maturity/match mapping, `index.ts` `enrichPending` single-flight runner triggered after scans, at boot, and by "Refresh all metadata" in settings), `src/lib/server/progress.ts` (watch positions, continue-watching, `loadProgress`/`applyProgress`/`withProgress` stamp a 0–1 `progress` **and `inWatchlist`** onto items + episodes in every browsing loader and the series watch loader (its `show` feeds the player's episodes panel); thresholds in client-safe `src/lib/data/progress.ts`; `dismissProgress` sets `watch_progress.dismissed_at` so a title leaves "Continue watching" until the next `saveProgress` clears it; `markWatched` writes a finished position for a movie / every episode of a series — one-way, no unwatch).

### Watchlist

**Watchlist** (`src/lib/server/watchlist.ts`, `watchlist` table with the same partial unique indexes as `watch_progress`): `POST /api/watchlist {kind, slug, inWatchlist}`, `/watchlist` page (`LibraryPage` with a "Recently added" default sort + empty state; in `ACCOUNT_PREFIXES`), navbar **Watchlist** link left of the avatar, and a ⋮ menu (`card-menu.svelte`, top-left of every `PosterCard`, signed-in only, always visible on touch) with Add/Remove (Show) to Watchlist and — on the home Continue-watching row only (`MediaRow continueWatching`) — "Remove from Continue watching" (`POST /api/progress/dismiss`). On that row a **series** tile shows and links straight to its episode (`continueTarget` in `src/lib/data/episodes.ts` = `playTarget` while it resumes: caption "S2E4 · Title", that episode's progress bar and rating badge, href `episodeWatchHref`); movie tiles still open the detail page. `continueWatching(profileId, overlay)` keeps a series in the row while `continueTarget` has an episode, so finishing an episode advances the tile to the next one and finishing the last episode drops it. Detail heroes: an oversized Play/Resume (movies: `Resume at 15m 25s` — elapsed units, never clock-style, which reads like a time of day — from `movieWatchState` passed as `DetailHero resume`, with a bare progress line under the poster; `formatDurationUnits` in client-safe `src/lib/data/time.ts`), then Watchlist toggle / **Mark as watched** (movies only: `POST /api/progress/watched {kind: 'movie', slug}`; disabled "Watched" once `progress === 1`) / Watch trailer. Series are marked **one episode at a time** from the ⋮ menu top-left of each episode card on the detail page (`episode-menu.svelte`, `EpisodeCard menu`; `{kind: 'series', slug, episodeSlug}` — there is no whole-series request). The finished row is stamped now, so Play/Resume and Continue watching move on to the next episode; browser calls live in `src/lib/watchlist-client.ts`. Movie detail pages show the source resolution (`getMovieDetail` → `Movie.sourceWidth/Height` from the best active `media_file`, rendered by `MetaPills` via `resolutionLabel`, "4K" for 2160p; list queries and series don't carry it).

### File-format tooltip

**File-format tooltip** (`media-format-tooltip.svelte`, bits-ui `Tooltip` with its own `Provider`): movies get it on that resolution badge (`Movie.format` from `getMovieDetail`), series on an ⓘ next to each episode card's runtime (outside the card's `<a>`; `Episode.format` from `getSeriesDetail`, the series detail loader only — best active file per episode). `MediaFormat` = container/size/bitrate/video codec/frame size + every `media_audio` stream (`fileFormats` in `catalog.ts`, one query; falls back to `media_file.audio_codec` for files scanned before audio-track discovery). The tooltip renders only the default audio stream (else the first) plus "+N more", to stay small — the player's Audio menu lists them all. Labels live in client-safe `src/lib/data/media-format.ts` (tested; also owns `channelLabel`). Tooltips ignore touch, so the trigger toggles on tap (state captured at `pointerdown`, handlers merged with `mergeProps` — spreading `props` then setting `onclick` would drop bits-ui's own) and a tap outside closes it.

### Auth gate

Auth gate lives in `hooks.server.ts` (redirect to `/login`; public: `/login`, `/register`, `/api/auth`, `/api/gateway/pair`; `/api/stream/*` short-circuits Better Auth entirely — stream URLs authorize by unguessable playback-session uuid).

### Roles

**Roles**: Better Auth `admin()` plugin (`user.role` = comma-separated string; helpers in client-safe `src/lib/auth-roles.ts`: `isAdmin`, `roleForNewUser`, `isRegistrationOpen`). The first account on an empty hub becomes `admin` (app-level `databaseHooks.user.create.before` in `auth.ts`); later sign-ups are `user`; `ensureAdminExists()` (`src/lib/server/users.ts`, run at boot) promotes the oldest account on installs that predate roles.

### Admin dashboard

**Admin dashboard** at `/admin/*` (shadcn `sidebar` layout, no navbar): Overview (`/admin`: six linked count tiles, Now playing (`listActiveStreams`, polls `/admin/statistics/activity` every 10 s), Recently watched, a Devices summary, Last 7 days (`summary(7, tz)` — the `finderella_tz` cookie path is `/admin` so the overview gets the zone too) and Recently added grouped one entry per movie/series), Devices (`/admin/devices`: pairing codes, libraries, rescan, rename/revoke/remove, and an **Activity log** — `device_event` (`gateways.sql.ts`; type list in client-safe `src/lib/data/device-events.ts` with the tested `describeDeviceEvent` wording) written by best-effort `recordDeviceEvent`/`queueDeviceEvent` (`src/lib/server/gateways/events.ts`) from the pair endpoint (credited to the code's creator), the page actions, `finalizeScan` (`scan.finished` + duration) and the trickplay job's `finally`; device/library/user FKs `set null` with name snapshots so entries outlive a revoke; revoking also deletes the pairing codes that device claimed (the FK would un-claim them and make them pairable again); the page is composed from `src/lib/components/devices/` (`device-card`, `library-row`, `pairing-dialog` with the key-cap code that notices a claim when the code leaves the reloaded `pendingCodes`, `thumbnail-job-card`; `copy-button.svelte` now lives in `src/lib/components/`); rename/add/revoke/remove are one page-level `Dialog`/`AlertDialog` each). Admin dialogs with form actions use `DialogForm` (`src/lib/dialog-form.svelte.ts`: `open`/`busy`/`error`/`target` + `submit` for `use:enhance` — closes on success, shows the `fail()` message inline and skips `update()` on failure so the page's `form.message` alert doesn't repeat it), Users (`/admin/users`: list/create/promote/demote/ban/unban/delete/set password via `auth.api.*` admin endpoints, a profile count per account; **Create account** is a header button + `Dialog`, row actions a ⋮ menu — **Watch statistics** link (every row), role/unban submit one hidden page form, Change password (`setUserPassword` + optional `revokeUserSessions`; not for yourself), Ban (reason) and Delete are dialogs), Subtitles (`/admin/subtitles`: provider keys, languages, auto-download, bulk job + history), Site settings (`/admin/settings`: **Require an account to access** (`site_settings.require_login`, default on) and **Allow visitors to register** (`allow_registration`) — independent switches posted from one form; a **Trickplay** card with the seek-bar thumbnails switch (`trickplay_enabled`, its own form/action so it can't blank the Access switches); catalog prune, TMDB API key (save/test/remove) + metadata refresh + TMDB attribution).

### Navbar

Navbar (`site-header.svelte`, shown only when signed in and outside `/admin`) has a far-right avatar dropdown with **Settings**, **Admin dashboard** (admins) and **Sign out** (`POST /logout`).

### Settings pages

**`/settings`** (any signed-in user; `src/routes/settings/+layout.svelte` = heading + a section menu — a sticky left column from `md` up, a row of pills below; the menu is two groups — **Account** (Account, Devices) and **Profile: <name>** (the active profile, its name shown as written after the upper-cased label; Preferences, Subtitles, Playback, Statistics; hidden until a profile is picked); below `md` the grid column is `minmax(0,1fr)` so the pill row scrolls instead of widening the page; `/settings` itself 307-redirects to `/settings/account`): **`/settings/account`** — display name (`auth.api.updateUser`), email (direct `user.email` update — no verification mail exists, and Better Auth's `changeEmail` refuses verified users) and password (`auth.api.changePassword` with `revokeOtherSessions`); **`/settings/devices`** — the account's signed-in sessions (see **Signed-in devices** below); **`/settings/subtitles`** — the per-profile subtitle defaults. **`/settings/playback`** — preferred audio language ("Original language" = the file's default track, value `'default'`) + **maximum audio channels** (both in the Audio card/form), play next episode automatically, and the "Still watching?" prompt (three cards/forms/actions). **`/settings/preferences`** — theme + screensaver. New sections (playback defaults later) are a sibling route + an entry in the layout's `sections` list. `/register` asks only for email + password (`displayNameFromEmail` in `src/lib/server/users.ts` seeds the name); password fields use `src/lib/components/password-input.svelte` (show/hide toggle; the two eye icons are rendered in an `{#if}` because `HugeiconsIcon` draws its `icon` prop once on mount and ignores later changes).

**Auto-save:** the per-profile sections (Preferences, Subtitles, Playback) have no Save buttons; every control saves itself when it changes. `SettingsSaver` (`src/lib/settings-saver.svelte.ts`, one per card) posts just the changed field to the card's existing form action. Those actions already take a partial patch, so missing fields stay untouched. The post uses `fetch` + `deserialize`, and saves run one at a time, in order. A `<SaveStatus>` in the card header (`Card.Action`) shows Saving… / Saved (for 3 s) / the error; a failure re-runs the loads so the controls show what's actually saved. Only Preferences re-runs the loads after a successful save (`invalidate: true`), because the root layout applies the theme and runs the screensaver from its own copy. The forms keep their `name`d fields, a `<noscript>` Save button and `autocomplete="off"`, which stops Firefox restoring stale values on reload.

### Signed-in devices

**`/settings/devices`** (account-level, reachable before a profile is picked) lists every unexpired Better Auth session of the account: device-type icon, "<browser> on <OS>" and when it was last used. The current session is first with a **This device** badge and no button; each other row has **Sign out** (`?/revoke`), and the card footer has **Sign out all other devices** (`?/revokeOthers`, confirmed in an `AlertDialog`). No IP address or location is shown.

- **Last used** is the session additional field `lastActiveAt` (`auth.ts`, `input: false`, migration `0025_session_last_active`). Better Auth's own `updatedAt` would move only on the daily refresh (`updateAge`); the stamp below bumps it too, through the Drizzle schema's `$onUpdate` (harmless: refresh and expiry are driven by `expiresAt`). It is per session, unlike admin statistics' "last seen" (`markSeen`, one `user_activity` row per account with the latest request's user agent). `hooks.server.ts` calls `markSessionActive` (`src/lib/server/account-sessions.ts`) on every authenticated request; it writes only when the value `getSession` loaded is null or over 5 minutes old, and a `pending` set dedupes concurrent requests. Rows from before the column fall back to `updatedAt`. It also fills an empty `session.user_agent` from the request (once, regardless of the throttle): Better Auth stores `""` when a server-side sign-in call gets no headers, which `/login` and `/register` did before they passed `event.request.headers`.
- **Listing** reads the `session` table directly (`listAccountSessions`): `auth.api.listSessions` runs `freshSessionMiddleware`, which answers 403 `SESSION_NOT_FRESH` for any session older than `freshAge` (1 day), and its rows carry the token. Tokens and IPs never leave the server; the page posts session **ids**, and `?/revoke` maps one to its token with `sessionTokenFor` (scoped to the user) before calling `auth.api.revokeSession`. It refuses the current session and treats an unknown id as already signed out. Browser/OS come from `parseUserAgent` (`src/lib/server/stats/user-agent.ts`); labelling and ordering are pure helpers in `src/lib/data/account-sessions.ts` (tested). Icons: `session-device-icon.svelte` shows the OS logo with the browser logo as a corner badge, monochrome (`currentColor`). The logos are from `simple-icons` (CC0, devDependency like hugeicons, named imports so only the used ones are bundled): Apple for macOS/iOS/iPadOS, Android, Linux, Chrome, Firefox, Safari, Opera, Vivaldi. simple-icons has no Microsoft logos, so Windows uses hugeicons' `WindowsNewIcon`. Any other OS falls back to the form-factor icon (`DEVICE_ICONS` from `platform-label.svelte`'s module script), and any other known browser (Edge, Samsung Internet…) to hugeicons' `BrowserIcon`. No badge when the browser is unknown.
- A revoked device is signed out on its next request (stream URLs authorize by playback-session id, so a video that's already playing keeps going until its next heartbeat or session start).
- **Session-storage assumptions (deliberate shortcut).** Listing (`listAccountSessions`, `sessionTokenFor`) and the activity stamp (`markSessionActive`) use Drizzle on the `session` table directly; only revoking goes through Better Auth (`revokeSession` / `revokeOtherSessions`). This bypasses Better Auth's `internalAdapter`, unlike `activeProfileId` (`setActiveProfile`). It is correct only while sessions live in Postgres with no cookie cache and no `databaseHooks.session.update`. The supported route is `(await auth.$context).internalAdapter`: `listSessions(userId, { onlyActiveSessions: true })` (no freshness check, unlike `auth.api.listSessions`; its rows include tokens, so keep the explicit mapping) and `updateSession(token, …)`. **Before enabling any of these, revisit this feature:**
  - **`session.cookieCache`**: `getSession` serves the session from a signed cookie for up to `maxAge` (default 5 min) without reading the DB, so a revoked device stays signed in until its cached cookie expires. Shorten `maxAge` or say so in the UI. `lastActiveAt`/`userAgent` then also come from the cache, so the throttle sees stale values and writes on most requests (the `user_agent` fill-in repeats too); add an in-memory per-session guard like `markSeen`'s map.
  - **`secondaryStorage`** (Redis etc.): sessions may not be in Postgres at all (or the DB copy lags), so the page lists nothing or stale rows and stamps are lost. Switch to `internalAdapter`.
  - **`databaseHooks.session.update`** (audit, validation): the raw `UPDATE` skips it. Switch the stamp to `internalAdapter.updateSession`.

### Account limits

Two hub-wide limits in **Admin → Site settings → Account limits** (`site_settings.max_sessions_per_account` / `max_profiles_per_account`, migration `0026_account_limits`; null = unlimited). Sessions default to unlimited, profiles to 5 (`DEFAULT_MAX_PROFILES`, the former fixed `MAX_PROFILES`). Each limit is a switch (off = unlimited) plus a 1–99 number (`LIMIT_MIN`/`LIMIT_MAX`); `?/updateLimits` is its own action and form (a shared form would blank settings it didn't post) and validates with zod in the action (`readLimit`), keeping zod out of the client-safe `src/lib/data/account-limits.ts`. They apply to every account, administrators included, and never delete anything.

- **Signed-in devices:** `databaseHooks.session.create.after` (`auth.ts`) runs `enforceSessionLimit` (`src/lib/server/session-limit.ts`) after every new session, so `/login`, `/register`, the raw `/api/auth/*` endpoints and any future sign-in method are covered. It lists the account's sessions through the hook context's `internalAdapter.listSessions(userId, { onlyActiveSessions: true })` and signs out the least recently used (`lastActiveAt` → `updatedAt` → `createdAt`) with `internalAdapter.deleteSession(token)`, until the account is back at the limit; pure `sessionsToEvict` (tested) never picks the new session. Admin impersonation sessions (`impersonatedBy`) neither count nor trigger eviction. Lowering the limit evicts nothing until the account's next sign-in, which then brings it all the way down. A failure (or a missing hook context) is logged and never fails the sign-in. Eviction is immediate only because no cookie cache is configured (see **Signed-in devices** → session-storage assumptions). `/settings/devices` states the limit when one is set.
- **Profiles:** `createProfile` (`src/lib/server/profiles.ts`) refuses with "An account can have up to N profiles." when `canAddProfile(count, limit)` is false; `/profiles` gets `maxProfiles` (`number | null`) for the Add tile and copy. An account over a lowered limit keeps its profiles and can't add more. Count-then-insert can race two concurrent creates past the limit by one (accepted, as before).

### Playback start

Watch pages create sessions client-side via `POST /api/playback/start` → `{mode: direct|hls, src, sessionId, quality}` (optional `quality` from the ladder in `src/lib/playback-quality.ts`: `original` = direct play when compatible else source-res transcode (≤3840 wide); `2160p|1080p|720p|480p|360p` force HLS with `-maxrate` caps for slow remote uplinks; responses carry `source.{width,height}`) (404/503 with a readable message when the title has no file / its device is offline); progress reports throttle to `/api/progress`; resume via `startAt`/`startSeconds`.

## Categories

(`src/lib/data/categories.ts` pure + tested: `CATEGORY_TYPES` = URL segments `genres|collections|networks` (param matcher `src/params/category.ts`), `genreSlug`/`genreFromSlug`, `groupCategories` (genre artwork = top-rated backdrop not already used, smallest genres pick first; collections need `MIN_COLLECTION_PARTS` = 2 movies, networks `MIN_STUDIO_TITLES` = 2 titles); `categoryHref` in `hrefs.ts`; server `src/lib/server/categories.ts` `categoryIndex` (narrow selects, no episodes) / `categoryDetail` (null → 404, same thresholds) via `listMoviesWhere`/`listSeriesWhere` in `catalog.ts`). Data from TMDB enrichment: `movie.studios`/`series.studios` = brand slugs → `studio` (slug/name/logo), `movie.collection_id` → `collection` (tmdb id/slug/name/art). Movies use `production_companies`, series `networks`; `studioBrand` (`metadata/map.ts`, `+` is significant so Disney+ ≠ Disney) merges a streaming brand's names (HBO/HBO Max/Max/HBO Films → `hbo`), anything else is `slugify(name)`. The canonical-name source's logo wins, and a logo is never overwritten with null. `category-tile.svelte`: backdrop tiles for genres/collections; network tiles flatten the logo (`brightness-0 dark:invert`). Prune deletes collection/studio rows nothing references. **`METADATA_VERSION`** (`metadata/index.ts`, currently 3 = episode ratings): matched titles below it are re-fetched by stored `tmdb_id` on the next non-forced pass (no re-search; series skip seasons unless they're below `SEASONS_VERSION`, the last version that added a season/episode field — raise it with `METADATA_VERSION` when that happens). Bump it whenever enrichment starts storing a new TMDB field. Episode ratings: `episode.rating` (nullable) from the season's `vote_average`, null while `vote_count` is 0 (`episodeRating` in `map.ts`); `EpisodeCard` shows it top-right like `PosterCard`.

## Subtitles

Discovered at scan time by the gateway and stored per file in `media_subtitle` (child of `media_file`, cascade; rows replaced on every scan that reports the file — gateways that predate subtitles omit `ProbedFile.subtitles` and keep their rows). **Embedded** text streams (`subrip`/`ass`/`ssa`/`webvtt`/`mov_text`/`text`, `packages/storage-gateway/src/subtitles/embedded.ts`) come from the same ffprobe JSON the scan already runs, stored with ffprobe's _absolute_ stream index; bitmap streams (PGS/VobSub/DVB) are skipped. **Sidecars** (`.srt/.vtt/.ass/.ssa`, `subtitles/sidecar.ts`, pure + tested) are matched from the video's folder, a `Subs`/`Subtitles` child folder and its immediate subfolders: name-prefix match (`Movie.en.forced.srt`), `Subs/<video name>/…`, or any file when the video is the only non-`sample` video in its folder; language/flags parse from the leftover tokens (`eng`, `2_English`, `forced`, `sdh`/`hi`/`cc`) via the shared table in `packages/protocol/src/languages.ts`. **Delivery**: `POST /api/playback/start` returns `subtitles: SubtitleTrack[]` (`src/lib/server/streaming/subtitles.ts` labels: "English", "English (SDH)", "French (Canadian)", `Track N`), each pointing at `GET /api/stream/<session>/subtitle/<id>.vtt`, which checks the row belongs to the session's file and proxies a `subtitle.get` tunnel message — the gateway converts everything to UTF-8 WebVTT (`subtitles/extract.ts`: srt/vtt in-process with a windows-1252 fallback for non-UTF-8 files, ass/embedded via `ffmpeg -map 0:<index> -f webvtt pipe:1`), caches the result under `tmpdir/finderella/subs/<hash>.vtt`, and streams the growing `.part` file while ffmpeg is still demuxing (`StreamTransfer`, `stream-transfer.ts`, same credit window as `FileTransfer`). **Player**: a hand-rolled Subtitles menu (right cluster, Off + one row per track; `c` toggles) drives our own `<track>` elements' `.track.mode` (`pickSubtitleTrack` in `src/lib/subtitle-preference.ts`: plain track in the preferred language → SDH → forced → the container's default track; English when nothing is set). **Per-profile subtitle settings** (`profile_settings` table, `src/lib/server/profile-settings.ts` `getSubtitleSettings`/`saveSubtitleSettings` + zod `SubtitleSettingsPatch`; client-safe options/defaults/`normalizeSubtitleSettings`/`cueLine`/`cueStyle` in `src/lib/data/subtitle-settings.ts`; cue size is `SIZE_SCALE` **percent of player height** emitted as `vh` — `::cue` percentages resolve against a small inherited size in Chromium and come out unreadable; the `/settings/subtitles` preview is a `@container-[size]` 16:9 box that scales the same number by `cqh` and steps position by `1.2em` lines; a track with unknown language (`und`, "Track N") is a session-only pick — `preferenceForTrack` returns null and nothing is persisted, and `normalizeSubtitleSettings`/`SubtitleSettingsPatch` accept only codes the language table knows): preferred language (off or a code), text size, color, background on/off (dark box; off = text-shadow instead), vertical position (0..`MAX_SUBTITLE_LINES` cue lines above the bottom edge → `VTTCue.line = -(n+1)`) and font (sans/serif/mono/casual). ## Browser remux

(playback mode `remux`, migration `0023`): files the browser can decode but not open (MKV, a non-first audio track, AC-3/E-AC-3) are re-wrapped **in the browser** into fragmented MP4 and played through MSE, instead of transcoding on the device. **Client**: `src/lib/playback-capabilities.ts` probes once per tab (`MediaSource ?? ManagedMediaSource` `.isTypeSupported` per codec, `AudioEncoder.isConfigSupported` for Opus/AAC stereo) and `startPlayback` sends `capabilities`; vocabulary + the pure `remuxPlan(file, audioCodec, caps)` in client-safe `src/lib/data/remux.ts` (ffprobe codec names; mkv/webm/mp4/m4v/mov; video h264/hevc/vp9/av1; audio copied when MSE takes it, ac3/eac3 `convert`ed when an encoder exists, else null → HLS; DTS/TrueHD stay HLS; **channels**: `remuxPlan(file, {codec, channels}, caps, maxAudioChannels)` returns `audioChannels` — copied audio passes through like direct play; a conversion keeps **5.1** when the viewer's resolved setting is 6, the track is exactly 6 channels and `caps.surround` (6-channel Opus encode + MSE 6-channel Opus playback, `decodingInfo`) is non-empty, else a surround viewer gets **null → the 5.1 HLS transcode** rather than a stereo remux; stereo/mono viewers get a stereo conversion). **Hub**: `POST /api/playback/start` tries direct → remux (Original quality only, `allowRemux`, `remuxEnabled()` = `site_settings.remux_enabled`, **Browser remux** card on `/admin/settings` with its own `?/updateRemux`) → HLS; remux needs neither ffmpeg nor `durationMs` on the device. A remux session reads the same range route as direct play (`/api/stream/<id>/file` accepts both) and answers `remux: { audioOrdinal }` (the chosen `media_audio` row's position among the file's streams — Mediabunny lists tracks in container order, same as ffprobe). **Player**: `src/lib/remux/pipeline.ts` (`runRemux`: Mediabunny `UrlSource` → key packet at/before the start → `EncodedPacketSink` → fragmented `Mp4OutputFormat` via `NullTarget` callbacks; audio copy, or AC-3/E-AC-3 decoded by `@mediabunny/ac3` WASM, `downmixToStereo` (ITU, normalized) and re-encoded) and `src/lib/remux/mse-player.ts` (`RemuxPlayer`: `prepare()` re-checks the exact mime and throws when unsupported, `start(at)`, 60 s ahead / 30 s behind buffer window, restart from the nearest key frame on an uncovered seek, stall watchdog, `destroy()`); `WatchPlayer videoKind='remux'` lazily imports it in the source effect (same `cancelled` guard as hls.js), `remuxAudioIndex`, and `onRemuxFailed(position, reason)` — both watch pages set `remuxBlockedFor` (title / episode) and restart with `allowRemux: false` at that position, like a quality change. `playerKind(mode)` maps session modes to player kinds. Mono downmix works on remux too (`createMediaElementSource` is fine on an MSE-backed element). Stats: `STREAM_MODE_LABELS`, `ActiveStream.remuxAudio`, `HistoryEntry.mode` (badge **Remux**); `transcoded` stays `mode === 'hls'`, so remux counts as not transcoded.

(markers; migration `0022`: `media_marker`, `media_file.chapters`/`markers_version`/`markers_analyzed_at`/`markers_error`, `site_settings.markers_enabled`, `profile_settings.skip_intro`/`skip_credits`). ### Audio channels (setting, detection, mono downmix)

**Audio channels** (`profile_settings.audio_channels`: `auto|mono|stereo|surround`, default `auto` — guests get it too, and on a stereo device it behaves exactly like `stereo`; client-safe `AUDIO_CHANNEL_OPTIONS`/`resolveAudioChannels` in `src/lib/data/playback-settings.ts`): `startPlayback` resolves the setting to `maxAudioChannels` 1/2/6 via `maxAudioChannels()` in `src/lib/audio-output.ts` (`auto` = `detectOutputChannels()`, `AudioContext.destination.maxChannelCount` ≥6 → 6, else 2, never mono; cached per tab and dropped on `navigator.mediaDevices` `devicechange`; `auto`/`surround` fall back to 2 when `canDecodeSurround()` — Media Capabilities for 6-channel `mp4a.40.2`, `media-source` or `file` — says no, and only an explicit no counts) and the start route turns it into `session.start.audioChannels` + a scaled `quality.audioKbps` via pure `transcodeAudio` (`src/lib/server/streaming/audio.ts`: 6 only when the chosen stream has ≥6 channels, ×2 bitrate; mono ½ with a 64k floor) → `hlsArgs` `-ac` (absent = 2, what old gateways always do). The scaled bitrate is kept on `HotSession.audioKbps` for the master playlist's `BANDWIDTH`. The native `aac` encoder takes `-ac 6` from any layout (5.1(side), 7.1 …) without an `aformat`. A cap **never** forces a direct-playable file into a transcode: surround passes through untouched (the browser downmixes), and mono is a Web Audio downmix in the player (`src/lib/audio-downmix.ts`, `WatchPlayer monoDownmix`, direct play only): `createMediaElementSource` → a gain node with `channelCount=1`/`explicit`/`speakers` → destination. `createMediaElementSource` is once-per-element (a second call throws) and once routed the element is only audible through the graph, so the graph is a per-element `WeakMap` entry built lazily by `setMonoDownmix(el, true)`, toggled mono/passthrough (`channelCountMode` `explicit`/`max`) by later calls, and disposed only by `releaseDownmix` from an effect whose cleanup runs when the `<video>` itself goes away. The player reads the flag through a `$derived` (`wantMono`), because the prop is built from the page's `playbackSettings`, which is recomputed on every `data` change (episode `goto`). Use `{ capture: true }`, not `true`, for the capture listeners: Node's `EventTarget` (used in the tests) ignores the boolean on `removeEventListener`. The context is resumed on `play`/pointerdown/keydown, because a suspended context plays the element silently. Element volume/mute still apply through the graph (verified).

### TMDB enrichment details

TMDB enrichment (`src/lib/server/metadata`) never rewrites `slug` or `hue`/`hue2` (slug = URL + ingest key). Both matched and unmatched titles get `metadata_updated_at` stamped, so scans don't re-search misses; only "Refresh all metadata" (force) retries. It also stores cast headshots (`cast_people` jsonb: name/character/photoUrl), season posters, episode stills, movie budgets and a YouTube `trailer_key` (`pickTrailer` in `map.ts`: trailer > teaser, official, English; `DetailHero` shows **Watch trailer** → `TrailerDialog` YouTube embed only when set). Artwork is hotlinked from `image.tmdb.org` (no hub-side cache); the settings page carries the required TMDB attribution.

**TMDB key.** `tmdbCredentials()` (`metadata/settings.ts`) resolves the key per request: the one saved on `/admin/settings` (Metadata card → `metadata_settings.tmdb_api_key`, a singleton row cached 5 s like `subtitle_settings`) wins, else `TMDB_API_KEY` from the environment, else none. `isTmdbConfigured()` is therefore async. The secret lives in its own table rather than `site_settings`, which every request reads and whose whole row `getSiteSettings()` returns. `saveTmdb` checks a new key with `testTmdbKey` (`GET /authentication`, valid for v3 keys and v4 tokens) **before** storing it, then fires a non-forced `enrichPending()`; a blank field keeps the saved key, the "Remove the saved key" checkbox falls back to the environment. The page only ever receives `maskSecret()` (`src/lib/data/secrets.ts`, shared with `/admin/subtitles`) and the key's `source` (`dashboard`/`env`).

### Filename parser

Filename parser (`catalog/parse.ts`): **movies** — the filename decides when it carries a year, else the nearest folder with one (`Inception (2010)/movie.mkv`), else the filename title stands. Year = bracketed `(2017)`/`[2017]` first, otherwise the _last_ plausible bare year before the release junk (`Blade.Runner.2049.2017` → 2017, title keeps 2049); plausible = 1888..next year, so `Blade Runner 2049.mkv` gets no year. **Series** — the `SxxEyy`/`1x02` marker comes from the filename, else the nearest folder (`Show S01E04 - Title/video.mkv`); the show title is the top-level folder cut at the first year / season-pack marker (`S01`, `Season 1-3`, `Complete`) / full episode marker, or the text before the marker for loose files; a missing show year falls back to the text before the marker (`Invincible.2021.S04E01`), never after it. Files whose name or folder says `sample` **and** that probe under 10 min are skipped at ingest (`isSampleFile`) — a feature-length title called "Sample" survives.
